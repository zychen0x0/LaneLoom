# LaneLoom 图像时序特征融合模块调研

## 结论

LaneLoom 可以去掉稠密的 Image-BEV 构造，把图像分支保持在透视图（Front View，FV）中。但不建议直接把三个时刻的同坐标特征做平均、TSM 或普通时序卷积，因为车辆运动会让同一条车道在不同帧中的图像位置发生明显变化。FGFA 的原始实验中，未做运动补偿的朴素多帧特征平均反而低于单帧基线；作者明确把跨帧空间错位视为视频特征聚合的核心问题。[FGFA 论文与实验](https://arxiv.org/abs/1703.10025)

本项目的首选方案是：

```text
每帧 RGB
  ↓ 共享 Image Backbone + 多尺度 FPN
{F_history, F_current}，每层 [B,T,C,H,W]
  ↓ 每个 FPN level 独立进行轻量可学习对齐
历史 FV → 当前 FV（deformable feature alignment）
  ↓ 轻量时序聚合
TAM 或 gated depthwise temporal convolution
  ↓
当前时刻的多尺度 Temporal-FV features

LiDAR 历史帧姿态对齐后拼接
  ↓ LiDAR Backbone
LiDAR-BEV feature

每层 Lane Decoder：
  3D Bézier query → 投影到 Temporal-FV 采样图像特征
                   → (x,y) 映射到 LiDAR-BEV 采样点云特征
                   → query 级门控/注意力融合 → refinement
  refined query → 再投影、再从两个平面采样 → 下一层
```

如果当前阶段只允许加入一个很小的模块，先做 `depthwise temporal convolution + current-frame residual gate` 作为可验证基线；如果它不能稳定超过单帧，再加入 deformable alignment。若直接追求更可靠的正式方案，推荐 `deformable alignment + TAM`，而不是更重的 ConvLSTM 或 VideoMamba。

## 先说明本项目中的两个约束

### 历史帧并不是相邻视频帧

当前配置按约 5 m、10 m 的车辆行驶距离选择历史图像，队列为 `(-10, -5, 0)`。这对静态道路几何有意义，但相对于常用的相邻帧视频模块，其透视图位移更大。因此，这套数据采样比普通动作识别更依赖特征对齐。相关配置见 [`configs/_base_/datasets/openlane_datasets.py`](../configs/_base_/datasets/openlane_datasets.py) 和 [`configs/main/laneloom_openlane_image_lidar_temporal.py`](../configs/main/laneloom_openlane_image_lidar_temporal.py)。

时序模块只知道三个离散槽位，并不知道真实时间间隔。因为这里主要感知道路这种静态结构，固定行驶距离比固定帧间隔未必更差，但应把相对位姿或行驶距离编码进对齐/融合模块，不能默认它是等时间间隔视频。

### 当前图像特征只有单一、较粗的 C5/FPN level

当前配置使用 ResNet50 的 `out_indices=(3,)`，即只取 C5，再输出单层 FPN。车道线是细长、需要精确定位的结构；如果取消 Image-BEV，建议至少恢复 C3/C4（stride 8/16）两级 FV 特征。时序模块应在各 FPN level 分别运行，输出一个多尺度列表，而不是先把不同分辨率强行拼起来。

## 候选模块比较

| 模块 | 输入到输出 | 额外计算/状态 | 跨帧对齐能力 | 多尺度 FPN 接入 | 对 LaneLoom 的判断 |
|---|---|---:|---|---|---|
| TSM | `[B,T,C,H,W]` → 逐帧特征，取当前帧 | 几乎零参数、零额外 FLOPs；仍需保留 T 帧特征 | 无 | 每层都可插；通常更适合插入 backbone residual block | 最便宜的 sanity baseline，但单独使用不适合 5/10 m 历史帧 |
| 固定 depthwise temporal conv | `[B,C,T,H,W]` → 取当前 slice | 很低；`k×1×1` depthwise 后接 pointwise | 无 | 最容易放在 FPN 后，每层一个模块 | 最适合第一阶段验证接口和训练链路 |
| TAM | `[B,C,T,H,W]` → 自适应聚合后的时序特征 | 较低；动态时间权重 | 无显式空间对齐 | 可在每个 FPN level 运行 | 推荐的轻量聚合器，但前面最好有对齐 |
| ConvGRU | 顺序读入 `[B,T,C,H,W]` → 最终 hidden | 中等；训练需展开 T 步，推理可缓存 hidden | 仅能隐式学习，不能保证几何对齐 | 每层独立 cell；高分辨率层成本较高 | 需要流式、可变长度历史时有价值；三帧离线队列不是首选 |
| ConvLSTM | 同上，输出 hidden/cell | 比 ConvGRU 更重，多一份 cell state | 仅隐式学习 | 同上 | 对短 T=3 性价比低，不建议优先 |
| 普通 3D Conv | `[B,C,T,H,W]` → 时空体 | 高于纯 temporal conv，尤其使用 `k×3×3` | 可在很小邻域隐式补偿 | 高分辨率 FPN 成本明显 | 不符合“轻量即插即用”的首选目标 |
| VideoMamba | 视频 token/patch 序列 → 视频表征 | 长序列复杂度有优势，但依赖专用 backbone/算子 | 没有针对驾驶透视几何的显式对齐 | 不是现成的 FPN fusion neck | 官方实现成熟到可训练视频模型，但对 T=3 属于过度设计 |

下面分别说明这些判断。

## 1. TSM：最便宜，但不是几何对齐

TSM 把一部分通道沿时间轴向前/向后平移，其余通道保持当前时刻，相当于让后续 2D 卷积看到邻帧信息。论文和官方项目强调它可以插入 2D CNN，并做到零新增参数、零新增计算；官方还提供了面向在线识别和视频检测的 causal/online 版本。[TSM 项目页](https://hanlab18.mit.edu/projects/tsm/)、[官方代码](https://github.com/mit-han-lab/temporal-shift-module)、[ICCV 2019 论文](https://openaccess.thecvf.com/content_ICCV_2019/papers/Lin_TSM_Temporal_Shift_Module_for_Efficient_Video_Understanding_ICCV_2019_paper.pdf)

优点：

- 改动最小，几乎不增加模型参数和 FLOPs。
- 可以复用 ImageNet 预训练的 2D backbone。
- 多尺度 FPN 的每层都能使用；也可以只在 ResNet 后半部分插入以控制显存。

局限：

- TSM 只移动通道，不移动空间坐标；历史 `(h,w)` 的特征仍被当作当前 `(h,w)` 的信息。
- 对动作分类，空间错位有时可以被后续卷积吸收；对车道线 x/z 几何回归，细线重影更可能直接伤害采样位置。
- 原始实现通常保留每个时刻的输出。本项目只需取当前时刻输出，必须保证训练和推理都没有使用当前帧之后的未来帧。

结论：适合作为“时序有没有任何收益”的零成本对照组，不应作为最终融合方案。

## 2. Depthwise temporal convolution：最合适的第一阶段基线

最小实现可以只在时间维卷积：

```text
[B,T,C,H,W]
  → permute [B,C,T,H,W]
  → depthwise Conv3d(C,C,kernel=(3,1,1),groups=C)
  → pointwise Conv3d(C,C,kernel=1)
  → 取 current slice
  → gate × temporal + current residual
```

PyTorch 的 `Conv3d` 原生接受 `[N,C,D,H,W]`；当 `groups=in_channels` 时，每个输入通道独立卷积，因此可直接构造 depthwise temporal convolution。[PyTorch Conv3d 官方文档](https://docs.pytorch.org/docs/stable/generated/torch.nn.Conv3d.html)

建议初始 gate 置零或很小，使模型一开始等价于单帧：

\[
F_{out}=F_t+\sigma(g)\,F_{temporal},\qquad g\text{ 初始化为负值}
\]

这样可以避免随机初始化的历史特征在训练初期破坏当前帧。它的目的不是解决对齐，而是用最低成本验证：数据队列、梯度、当前帧索引、FPN 形状和推理延迟是否正确。

## 3. TAM：推荐的轻量聚合器

TAM 针对固定时序卷积无法适应不同视频运动速度的问题，为每段视频生成自适应时间核。它由两部分组成：局部分支用短时间卷积产生位置敏感的重要性， global 分支根据整段视频产生聚合核；计算主要建立在空间池化后的时间信号上。论文把输入明确写为 `C×T×H×W`，并将 TAM 作为可以插进 2D CNN 的轻量模块。[TAM 论文](https://arxiv.org/abs/2005.06803)、[作者官方代码](https://github.com/liu-zhy/temporal-adaptive-module)

TAM 已经被 OpenMMLab 的 MMAction2 收录，当前文档中有 `TAM` 和 `TANet` 模块，因此比只存在于论文中的模块更容易迁移到本项目的 MMEngine/MMCV 技术栈。[MMAction2 官方仓库](https://github.com/open-mmlab/mmaction2)、[MMAction2 TAM API](https://mmaction2.readthedocs.io/en/latest/api.html#mmaction.models.common.TAM)

为什么它比固定时间卷积更适合本项目：

- 不同车速、历史帧实际间隔和图像质量下，三个时刻不应使用完全固定的权重。
- 可学习降低模糊、遮挡或过曝历史帧的贡献。
- 比 ConvGRU/ConvLSTM 更容易并行处理三个时刻。

但 TAM 的自适应时间权重不等于空间对齐。它可以决定“更信任哪一帧”，不能保证该帧中同一条车道落到当前正确像素。所以正式方案仍应在 TAM 前增加对齐。

## 4. ConvGRU / ConvLSTM：能保存记忆，但不是免费对齐器

ConvLSTM 用卷积替换全连接 LSTM 的输入到状态、状态到状态变换，从而在 hidden/cell map 中保留空间结构；这是其原始论文的核心设计。[ConvLSTM 原始论文，NeurIPS 2015](https://papers.nips.cc/paper_files/paper/2015/hash/07563a3fe3bbe7e3ba84431ad9d055af-Abstract.html)

ConvGRU 同样用卷积和共享空间权重构造 GRU 状态，原始视频表征工作使用 CNN 不同层级的 feature map 进行卷积式 GRU 建模。[ConvGRU 视频表征原始论文](https://arxiv.org/abs/1511.06432)

适用条件：

- 推理是连续视频流，希望跨任意长度维持 hidden state。
- 不想固定 `T`，且需要在序列边界显式重置状态。
- 后续可能加入 flow/deformable warp，将旧 hidden 先对齐到当前再更新。

不优先用于当前实验的原因：

- 目前只有两个历史时刻和一个当前时刻，长记忆优势尚未体现。
- 256 通道、3×3 的 recurrent gates 在高分辨率 FPN 上并不轻；ConvLSTM 还要保存 hidden 和 cell。
- 门控能拒绝不可靠历史，但无法保证旧 hidden 的 `(h,w)` 对应当前同一物理位置。驾驶相机运动大时，hidden 仍会重影。
- 多层 FPN 要么为每层建立独立 cell，要么先压缩通道；两者都比 TAM/temporal-DWConv 更复杂。

若必须选择 recurrent module，优先 bottleneck ConvGRU：先 `1×1` 把 C=256 压到 64/96，在 P3/P4 分别运行，再投回 256，并把当前帧 residual 保留下来。

## 5. 3D convolution：可以工作，但要区分两种形式

`kernel=(3,1,1)` 的纯时间卷积只在 T 维混合，同 depthwise/pointwise 分解后非常轻；`kernel=(3,3,3)` 则同时做时空卷积，计算、参数和激活显存都明显增加。

普通 3D 卷积允许在一个固定的小邻域吸收轻微像素位移，但 5/10 m 历史帧产生的透视位移远大于一个 3×3 邻域，而且远近区域位移不同。因此不建议为了“隐式对齐”堆叠重型 3D CNN。LaneLoom 应使用 2D backbone 保留预训练优势，仅在 FPN 后加入轻量时间核。

## 6. VideoMamba：实现成熟，但不是当前问题的即插即用答案

VideoMamba 使用状态空间模型处理短期和长期视频，论文强调其线性复杂度和长视频扩展性；官方仓库提供视频单模态训练代码、模型以及 Apache-2.0 许可。[VideoMamba 论文](https://arxiv.org/abs/2403.06977)、[官方代码](https://github.com/OpenGVLab/VideoMamba)

但它目前更像完整视频 backbone，而不是“输入几个 FPN feature maps，输出当前 FV feature”的 neck。将它改成多尺度 FPN 插件还需要解决 token 展平、空间位置编码、current-frame readout、Mamba CUDA 依赖和预训练迁移。对于 `T=3`，线性长序列优势没有发挥空间，也没有解决驾驶透视错位。因此当前不建议引入；只有历史窗口扩展到十几帧以上、轻量对齐已经解决后，才值得重新评估。

## 为什么正式方案需要 deformable alignment

FGFA 使用光流把邻帧 feature map warp 到参考帧，再进行自适应加权。其消融实验显示，不使用运动补偿的直接平均低于单帧，而 flow-guided aggregation 明显改善快速运动目标。这不是 OpenLane 上的直接证据，但清楚说明“时间融合”和“空间对齐”是两个问题。[FGFA 论文](https://arxiv.org/abs/1703.10025)、[FGFA 官方代码](https://github.com/msracver/Flow-Guided-Feature-Aggregation)

对于 LaneLoom，不建议第一版直接加入一个完整光流网络：

- 增加模型、显存和预训练依赖；
- 车道区域纹理弱、存在遮挡和曝光变化，像素光流未必可靠；
- 当前历史帧跨度较大，光流估计更难；
- 像素光流并不知道车道的三维静态几何。

更合适的折中是 STSN 风格的 feature-level deformable alignment：把当前与历史 FPN feature 拼接，预测历史 feature 的采样 offset/mask，直接以 lane detection loss 学习从邻帧何处取证据。STSN 的原始工作使用跨时间 deformable convolution 学习采样邻帧特征，不需要光流监督。[STSN 论文](https://arxiv.org/abs/1803.05549)、[ECCV 2018 官方论文页](https://openaccess.thecvf.com/content_ECCV_2018/html/Gedas_Bertasius_Object_Detection_in_ECCV_2018_paper.html)

建议每个 FPN level 执行：

```text
offset_k, mask_k = OffsetNet([F_current, F_history_k, pose_embedding_k])
aligned_k = ModulatedDeformConv(F_history_k, offset_k, mask_k)
F_temporal = TAM([aligned_history..., F_current])
F_out = F_current + gate * F_temporal
```

其中 gate 最好是逐位置或逐通道置信度，保证遮挡、历史缺失、序列开头重复帧时能退回当前帧。相对位姿/行驶距离可作为 OffsetNet 的条件，但不应把单一 2D 仿射或 homography 当作完整对齐：道路高度变化和透视深度会让图像位移随位置变化。

## 与 LiDAR 的融合位置

如果不构造 Image-BEV，没必要强行做稠密 FV-to-BEV fusion。最自然的融合位置是已有的 3D lane queries：

```text
一条 3D query 的 51 个采样点
  ├─ 用相机矩阵投影到 Temporal-FV 的 P3/P4，grid_sample
  └─ 用 (x,y) 映射到 LiDAR-BEV，grid_sample

[query feature, FV sampled feature, LiDAR-BEV sampled feature,
 projection-valid mask, lidar-valid mask]
  ↓ gated fusion / small cross-attention
  ↓ Decoder Layer 0 refinement
  ↓ 重新投影、重新采样两个特征平面
  ↓ Decoder Layer 1 refinement
```

这种 query-level fusion 有几个优势：

- 图像保留透视图高分辨率，不必承担不可靠的单目深度 lifting。
- LiDAR 保留真实 `(x,y,z)` 几何以及 BEV 道路结构。
- 只沿 50 条候选曲线采样，计算量远小于全图稠密跨模态注意力。
- 两层 decoder 每次都在更新后的曲线上重采样，图像与 LiDAR 证据会随几何 refinement 同步更新。

注意 LiDAR-BEV 已经压缩了 z 维，因此它主要提供平面位置、点云结构和由 LiDAR 分支预测的坡度先验；精确 z 仍需由 LiDAR geometry head、query state 与图像证据共同回归。

## 推荐实验顺序

不要同时替换 Image-BEV、时序模块、多尺度 FPN 和跨模态 fusion 后只看一个最终 F1。建议按以下顺序保留可解释的对照：

1. **单帧 FV 基线**：去掉 Image-BEV 时序路径；恢复 P3/P4；每层 decoder 从 FV 与 LiDAR-BEV 分别采样并融合。
2. **无对齐的最小时序基线**：P3/P4 后加入 gated depthwise temporal convolution，gate 近零初始化；与单帧比较。
3. **聚合器对照**：在相同输入和参数预算下，把 temporal-DWConv 替换成 TAM；TSM 只作为零参数对照。
4. **加入 deformable alignment**：先在 P3 使用，再视显存加入 P4；检查可视化 offset、历史帧权重和车道采样响应。
5. **最后才比较 ConvGRU**：仅当目标变为持续流式记忆，而不只是三帧 clip 时进行。
6. **暂不测试 VideoMamba**：除非历史长度明显扩展，而且上述轻量模型已经成为瓶颈。

至少报告：单帧与时序 F1、近/远场 x/z error、可见首尾误差、每帧延迟、峰值显存，以及历史帧缺失时是否能退化到单帧。特别要分开看直道、急弯、坡道、遮挡和强曝光；只看总 F1 很难判断时序模块究竟修复了哪类问题。

## 最终选择

综合几何可靠性、接入成本和当前三帧规模，排序如下：

1. **正式方案：多尺度 deformable alignment + TAM + current residual gate。**
2. **第一阶段工程基线：gated depthwise temporal convolution。**
3. **最低成本对照：TSM。**
4. **流式长记忆备选：bottleneck ConvGRU。**
5. **暂不采用：ConvLSTM、重型 3D Conv、VideoMamba。**

最重要的设计原则不是选择名字最新的时序模块，而是保证：历史特征先对齐到当前 FV，再融合；融合后的 FV 在每层 query refinement 后重新投影采样。
